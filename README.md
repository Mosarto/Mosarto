## About

I build complete digital products — the Flutter client, the Python service behind it, and the GLSL shader that draws the frame.

My work sits where **software engineering**, **applied AI** and **product thinking** overlap, and I own features end to end: data modelling, API contracts, authentication and quota boundaries, state management, motion design, containerisation and deployment. What I care about is the half of the system that only shows up when things go wrong — identity derived from a verified token instead of the request body, a failed model call that refunds the reserved quota slot instead of consuming it, roughly thirty gesture updates a second routed around React state rather than through it.

Recent work centres on **retrieval-augmented generation and semantic memory**: vector storage, local multilingual embeddings, compact prompt assembly, background profile enrichment, and LLM orchestration with strict structured-output validation. Alongside that I maintain **[Artomos](https://artomos.com)**, the independent studio I publish this work under.

I have been writing Flutter since 2021, and the interface studies further down this profile are the deliberate practice that preceded the production work.

<summary><b>Aether — Reflective AI Journal</b></summary>

<br />

A Flutter client for guided introspection. Users write freely or start from a structured reflection, then talk with **Nyx**, an AI presence written to answer with clarity rather than generic encouragement. A conversation can be distilled into an **Akashic Record** — a summary carrying emotional signals, recurring themes, tags and a key insight — and the archive collects those records over time.

| | |
|:---|:---|
| **Stack** | Flutter · Dart `^3.11` · Firebase Auth · Cloud Firestore · Firebase Cloud Messaging · `flutter_animate` · `CustomPainter` |
| **Scope** | Six main screens — Home, Reflection chat, AI tools, History, Record detail and Settings — plus four AI tools: dream, aura, stoic and synchronicity |
| **Performance** | Deliberately lightweight state: `setState` for local interaction, `ChangeNotifier` singletons for shared state, `StreamBuilder` for live Firestore data, repository injection for testable access |
| **Security** | Product routes require a verified Firebase ID token; committed Firebase configuration contains placeholders only, and the repository instructs contributors never to commit `.env` files, service accounts, keystores or signing properties |
| **Testing** | `fake_cloud_firestore` and Mockito covering models, repositories, chat state, freemium synchronisation, trackers, summaries and paywall navigation |
| **Repository** | **[Mosarto/aether](https://github.com/Mosarto/aether)** |

Aether is the client half of a two-repository product and does not function without its backend — a constraint the README states plainly rather than hiding. The interface is built from `CustomPainter` orbs, particles and constellations, `flutter_animate` transitions, Phosphor icons and Google Fonts, on a cyber-minimal design system carried across multiple themes.

</details>

<details>
<summary><b>Aether API — RAG & Semantic Memory Backend</b></summary>

<br />

The FastAPI service behind Aether. It authenticates Firebase users, retrieves relevant memories from Qdrant, assembles compact retrieval-augmented context, generates responses through an OpenAI-compatible provider, and returns data already shaped for the Flutter client.

| | |
|:---|:---|
| **Stack** | FastAPI · Uvicorn · Python 3.12 · Qdrant · FastEmbed · Firebase Admin SDK · Docker Compose · Dokploy |
| **Scope** | Sixteen endpoints, four AI-tool endpoints, background jobs for session compression and enriched-profile updates, and Qdrant collections for reflections, memories, conversations and profiles |
| **Performance** | Local 384-dimension multilingual embeddings remove a network round-trip from the retrieval path; a 20-turn sliding window bounds context growth; transient failures retry with capped exponential backoff honouring `Retry-After`, while permanent 400/401/403/404 responses never retry |
| **Security** | Every product route requires a verified Firebase ID token, and the user ID is derived from that token — request bodies cannot supply or override ownership; session reads, continuations and deletions are owner-scoped; per-user quotas and rate limits are enforced server-side; logs do not contain credentials, prompts or user content |
| **Failure handling** | An unavailable provider returns `503 {"error": "llm_unavailable"}` and refunds the reserved quota slot; `GET /health` is the only unauthenticated route |
| **Repository** | **[Mosarto/aether_api](https://github.com/Mosarto/aether_api)** |

All completions pass through one async layer. Use cases are separated by policy — temperature, token ceiling, timeout, retry budget — rather than by swapping models, which keeps behaviour predictable across chat, structured tasks and background jobs. Structured responses are parsed strictly and validated with Pydantic; an invalid answer gets exactly one corrective retry at lower temperature before the request fails honestly.

</details>

<details>
<summary><b>DITHER.CAM — Real-Time GPU Dithering & Gesture Control</b></summary>

<br />

A camera app with no buttons in the way. A webcam feed is rendered as a 1-bit ordered dither, as structure-aware ASCII, or as a CRT that has lost vertical sync — and effect, palette, hue, zoom and rotation are all driven by hand gestures in front of the lens.

| | |
|:---|:---|
| **Stack** | TypeScript 7 (strict, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`) · React 19 · three.js 0.185 · `@react-three/fiber` 9 · `postprocessing` 6 · MediaPipe `tasks-vision` · Vite 8 · nginx 1.27 on Alpine |
| **Scope** | Three effects across three palettes, plus mirrored tiling, frame freeze and PNG export — with exactly four runtime dependencies: React, three.js, postprocessing and MediaPipe |
| **Performance** | The three effects share one shader selected by a `uMode` uniform, because swapping `EffectComposer` children rebuilds the pass — a shader recompile — which under finger-count jitter would happen several times a second; roughly thirty gesture values per second bypass React state entirely, going into a mutable object read inside `useFrame` while React receives only a throttled HUD snapshot |
| **Privacy** | Video decode, hand tracking and the effect itself all run on the user's machine. No frame ever leaves the browser, and the container needs no outbound network at runtime |
| **Deployment** | Live at **[dither.artomos.com](https://dither.artomos.com)**, with a full keyboard fallback for every gesture — hand tracking can always be unavailable, whether the camera is denied, the model is missing or the CPU is too slow |
| **Repository** | **[Mosarto/dither.cam](https://github.com/Mosarto/dither.cam)** |

The ASCII mode is structure-aware: a Sobel pass inside each cell selects a stroke glyph aligned with the dominant edge, falling back to a tone ramp where there is no structure. The pipeline stays in raw sRGB — `LinearSRGBColorSpace`, `NoToneMapping`, colours passed as `Vector3` rather than `THREE.Color` — which is what makes `#131210` come out of an exported PNG as exactly `19,18,16`.

</details>

## Engineering Practices

<div align="center">

| Practice | Where it shows up |
|:---|:---|
| **Trust boundaries drawn once** | Aether API derives user identity from a verified Firebase ID token; request bodies cannot supply ownership fields |
| **Quota-safe provider failure** | A `503 llm_unavailable` response refunds the reserved quota slot rather than consuming it |
| **Local camera processing** | DITHER.CAM keeps every frame on the machine — no upload, no server, no tracking, and no outbound network from the container at runtime |
| **Secret-handling discipline** | Firebase configuration is placeholder-only, and the Aether README instructs contributors never to commit `.env` files, service accounts, keystores or signing properties |
| **Strict typing and validation** | DITHER.CAM enables `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess`; Aether API validates every structured LLM response with Pydantic |
| **Content-minimising logs** | Aether API logs and errors carry no credentials, prompts or user content |
| **Tests where regressions hurt** | Models, repositories, chat state, freemium synchronisation, trackers, summaries and paywall navigation, via `fake_cloud_firestore` and Mockito |
| **Accessible alternatives** | Artomos honours `prefers-reduced-motion`; DITHER.CAM gives every gesture a keyboard equivalent |
| **Container deployment** | Docker Compose, Dokploy and nginx on Alpine, documented in the repositories rather than living on one machine |
| **Minimal dependency surface** | Four runtime dependencies in DITHER.CAM; locally served fonts and assets in Artomos |
